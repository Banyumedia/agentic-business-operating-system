# TX-01 — Kunci fiskal + benahi cacat tarif 0% (D-74)

Branch `task/TX-01`, dikerjakan langsung di worktree utama karena **SERIAL**
(migration). `main` bersih dan bebas writer saat dikerjakan (`bcae5f2`, setelah
lead-capture D-76 mendarat). Bukti di sini; dilipat ke `AUTOPILOT_STATUS.md` saat
tidak ada writer paralel.

## Cacat yang ditutup

Tenant `taxable` di jalur Eloquent memungut **0%** sementara jalur JSON memungut
**11%** untuk konfigurasi yang sama. Akarnya di `BusinessIdentityStore::taxProfile()`:
`$rate = $identity['tax_rate'] ?? self::DEFAULT_RATE`. Kolom `tax_rate` berdefault
`0.00` (migration `2026_09_17_222047`), jadi nilai `0.0` datang bukan `null` — `??`
tidak menyala, tarif jadi 0. Jalur JSON tanpa kunci `tax_rate` mendapat `null`,
jatuh ke `DEFAULT_RATE` 0.11. Dua sumber data menjawab pajak berbeda.

## Yang berubah

- **Migration baru** `2026_09_24_110000_add_fiscal_lock_and_fix_tax_rate_default`:
  - `fiscal_locked_at` (nullable timestamp) — sumber kebenaran eksplisit untuk
    penguncian pilihan pajak (dipakai TX-03), bukan disimpulkan dari data lain.
  - `tax_rate` kehilangan default `0.00` → nullable murni. Baris lama bertarif
    `0.00` **tidak** diubah massal (mengubahnya mengganti arti data lama);
    `change()` dibungkus try/catch karena butuh dukungan driver, dan keamanan
    fiskal tidak bergantung padanya — penolakan ditegakkan di store.
  - Portabel Schema Builder (B-01).
- `app/Models/BusinessIdentity.php`: `fiscal_locked_at` masuk fillable + cast
  `datetime`.
- `app/Services/BusinessIdentityStore.php`: untuk `taxable`, tarif `null`
  **maupun** `0` (dan negatif) **ditolak** `InvalidArgumentException` — PKP yang
  memungut 0% adalah konfigurasi mustahil, bukan pilihan yang ditambal default.
  `non_taxable` tetap tidak menuntut tarif.

## Keputusan yang dikunci test (negatif lebih dulu)

- `taxable` + tarif `null` → ditolak.
- `taxable` + tarif `0` → ditolak.
- `taxable` + tarif eksplisit 11 → profil 11%, inklusif sesuai flag.
- `non_taxable` tanpa tarif → sah, rate 0.
- Kolom `tax_rate` tak lagi punya default 0.00 tersembunyi (identitas tanpa
  tarif = `null`).
- `fiscal_locked_at` default null, bisa dicap.
- Baris lama bertarif `0.00` tetap tersimpan apa adanya (identitas lama tidak
  berubah arti).
- **Paritas JSON ↔ Eloquent**: konfigurasi taxable rate 11 menghasilkan
  `TaxProfile` identik di kedua jalur (mengunci cacat inti).

8 test baru di `tests/Feature/BusinessIdentityFiscalTest.php`.
