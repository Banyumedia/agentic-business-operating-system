# MP-07 — Buat booking dari kalender lewat `BookingService`

Status: **DONE**.

## Keputusan desain

- **Dual-path seperti `CashierScreen` (MP-02)**, bukan Eloquent-only seperti
  MP-02/MP-09/MP-10: `bookings`/`resources` sama-sama punya schema JSON
  (D-42), dan `JsonEntityRepository` **sudah** menegakkan `no_overlap` secara
  generik untuk entitas apa pun yang mendeklarasikannya di schema
  (`assertNoOverlap()` di `JsonEntityRepository.php`, dipasang sejak sebelum
  task ini untuk keperluan lain). Jalur JSON cukup `EntityRepository::save()`
  — tidak perlu servis tambahan. Jalur Eloquent lewat `BookingService::create()`
  supaya aturan tabrakan (`assertNoOverlap()` versi Eloquent) hanya hidup di
  satu tempat, sesuai larangan eksplisit acceptance ("jangan ditulis ulang di
  layar").
- **Hanya entitas `bookings` yang menulis.** `CalendarScreen` melayani
  entitas lain juga (dicek: registry punya `bookings`/`pipeline`/dll dengan
  pola `calendar` — task ini secara spesifik menyasar kalender booking).
  `requestCreate()`/`create()` menolak diam-diam (bukan error) bila entitas
  aktif bukan `bookings`, supaya layar kalender untuk entitas lain (bila ada)
  tidak tiba-tiba menampilkan tombol tambah yang tidak berfungsi.
- **Tahap awal dari alur kerja preset** (`initialStage()`, pola identik
  `CashierScreen`), bukan hardcode `'draft'` — booking baru langsung masuk
  ke tahap pertama preset aktif (mis. `dijadwalkan` untuk salon).

## Cacat nyata ditemukan saat menulis test (bukan diasumsikan)

`BookingService::assertNoOverlap()` (kode pra-ada, bukan ditulis task ini)
membandingkan `starts_at`/`ends_at` sebagai **string leksikal** lewat query
builder (`where('starts_at', '<', $endsAt)`). Kolom `dateTime` Eloquent/SQLite
menyimpan dengan format `Y-m-d H:i:s` (spasi). Saat saya awalnya mengirim
waktu berformat ISO `Y-m-d\TH:i:s` (huruf `T`) ke `BookingService::create()`,
perbandingan leksikal antara format bercampur (`T` terkirim vs spasi
tersimpan) **gagal mendeteksi tabrakan jadwal yang sesungguhnya tumpang
tindih** — booking kedua tersimpan begitu saja tanpa exception. Test
`test_negative_overlapping_slot_is_rejected_on_eloquent_driver` menangkap ini
langsung (bukan lolos secara kebetulan). Ditutup dengan mengirim
`Y-m-d H:i:s` (spasi) khusus untuk jalur Eloquent, sesuai format storage
sungguhan — jalur JSON tetap ISO karena `JsonEntityRepository::assertNoOverlap()`
membaca lewat `strtotime()` yang menerima kedua format.
