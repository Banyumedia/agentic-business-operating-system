# TX-02 — Onboarding menanyakan mode pajak + harga inklusif (D-74)

Branch `task/TX-02` dari `main` (`da27895`, di atas TX-01). Menyentuh hanya
`app/Livewire/Onboarding.php` + view-nya dan dua test onboarding — disjoint dari
lajur Hermes/lead-capture, tanpa migration/route/berkas bersama.

## Cacat yang ditutup

`Onboarding.php` menulis `tax_mode = 'non_taxable'` + `price_includes_tax = true`
**hardcode** dan tidak pernah bertanya, padahal D-44 (2026-09-16) menjanjikan
onboarding menanyakannya sekali. Komponen bahkan tidak punya properti untuk
jawaban tenant. Jalur JSON tidak menulis `price_includes_tax` sama sekali.

## Yang berubah

- Properti baru `taxable` (default false) dan `priceIncludesTax`.
- Langkah identitas (step 1) menampilkan satu pertanyaan bahasa awam: *"Usaha
  Anda memungut PPN (sudah PKP)?"* default **tidak**. Bila **ya**, muncul
  pertanyaan kedua inklusif/eksklusif — **tidak dirender sama sekali** bila
  non-PKP (D-44 zero-bloat, bukan disabled). Pertanyaan kedua menyertakan
  **contoh nominal konkret**: PPN 11% pada harga Rp100.000 → pelanggan bayar
  Rp111.000 (belum termasuk) atau Rp100.000 (sudah termasuk).
- `fiscalAttributes()` menulis satu bentuk untuk **kedua jalur** (Eloquent +
  JSON, paritas D-42): non-PKP → `tax_mode=non_taxable`, `tax_rate=null`
  (bukan 0% yang menyamar); PKP → `tax_mode=taxable`, `price_includes_tax`
  sesuai jawaban, `tax_rate=11` **eksplisit** (bukan default kolom, cacat TX-01).
- `fiscal_locked_at` dicap `Carbon::now()` di kedua jalur — pilihan terkunci
  begitu usaha dibuat (dipakai TX-03 untuk menegakkan penolakan ubah).
- Ringkasan pajak ditambahkan ke langkah review (step 3).

## Keputusan yang dikunci test

- Jawaban tenant **benar-benar tersimpan** — test RED langsung terhadap perilaku
  hardcode lama (Eloquent: taxable rate 11 + lock; JSON: identitas menulis
  `price_includes_tax` + `tax_rate` + `fiscal_locked_at`).
- Non-PKP **tidak pernah** menyimpan `tax_rate` bermakna walau `priceIncludesTax`
  kebetulan true di komponen (D-44).
- Tarif tersimpan **eksplisit** (`11.00`), bukan default tersembunyi.
- Paritas JSON ↔ Eloquent pada bentuk identitas.
- Tenant taxable hasil onboarding mendapat `TaxProfile` benar 11% (menutup rantai
  cacat TX-01 end-to-end lewat form).

30 test onboarding hijau (24 di `OnboardingEloquentTest`+`OnboardingTest`, 6
`OnboardingFlowTest`); yang lama tak berubah selain ekspektasi default identitas
yang kini menyertakan `fiscal_locked_at`.

## Sisa (bukan lingkup TX-02)

  `fiscal_locked_at` terisi) + tampilan alasan terkunci. `fiscal_locked_at` sudah
  siap dari sini.

  lewat jalur setelan, bukan onboarding — konsisten dengan D-74 yang mengunci
  pilihan setelah pendaftaran.
